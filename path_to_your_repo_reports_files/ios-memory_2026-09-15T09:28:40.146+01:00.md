# Network Assessment Report

## Executive Summary

A memory utilization assessment was conducted across all network devices in the testbed inventory. The command `show processes memory` was executed on all four IOS-XE devices — `R1`, `R2`, `SW1`, and `SW2` — to retrieve real-time Processor Pool memory statistics. **All four devices are operating well within healthy memory utilization thresholds**, with no device exceeding the 80% alert threshold. No issues are raised as a result of this assessment.

---

## Scope & Assumptions

- **Devices in scope:** All devices present in the testbed inventory — `R1`, `R2`, `SW1`, `SW2` — all running **IOS-XE** on the IOL platform.
- **OS types checked:** IOS-XE (all four devices). No IOS or IOS-XR devices were found in the inventory.
- **Memory metric source:** Processor Pool statistics extracted from `show processes memory` (first summary line per device).
- **Alert threshold:** Memory utilization **> 80%** triggers an issue flag; ≤ 80% is considered healthy and no alert is raised.
- **Note:** The command `show processes memory summary` was not supported on this platform variant (IOL); the full `show processes memory` output was used instead, with the Processor Pool summary line parsed for total, used, and free values.
- **No IOS or IOS-XR devices** were present in the inventory at the time of assessment. The scope was limited to the discovered device set.

## Analysis & Findings

Memory values are sourced from the **Processor Pool** line of `show processes memory`. Utilization is calculated as:

> **Utilization (%) = (Used / Total) × 100**

### Key Observations

- **`R1` and `R2`** share identical Processor Pool sizes (~782 MB total) and nearly identical used memory (~128 MB), indicating symmetric provisioning and consistent process loads on both routers.
- **`SW1` and `SW2`** share identical Processor Pool sizes (~777 MB total) and nearly identical used memory (~107 MB), consistent with mirrored switch configurations.
- All devices have **over 83% free memory**, leaving significant headroom for additional processes, routing table growth, or traffic spikes.
- The router pair (`R1`/`R2`) has a slightly higher used memory than the switch pair (`SW1`/`SW2`), which is expected given the additional routing process load (e.g., `CEF: IPv4 process`, `Crypto CA`, `IP ARP Adjacency`, `EEM Server`).

---

## Risks & Considerations

- **No current memory risks identified.** All devices are operating at well below the 80% threshold.
- **Symmetric device pairs** (`R1`/`R2` and `SW1`/`SW2`) show near-identical memory profiles, which is expected in a lab/IOL environment. In production, deviations between paired devices could indicate process anomalies or configuration drift.
- **Platform note:** These devices run on the **IOL** (IOS on Linux) platform, which may not precisely reflect memory behavior of physical hardware at scale. Memory values should be interpreted in the context of the virtualized environment.
- **IOS / IOS-XR gap:** No IOS or IOS-XR devices exist in the current inventory. If such devices are added in the future, a separate memory assessment should be conducted, as command syntax and memory pool structures differ (e.g., `show processes memory platform` on IOS-XR).

---

## Recommendations

- **No immediate action required.** Memory utilization is healthy across all polled devices.
- **Establish a memory monitoring baseline** using the current values (~16% for routers, ~14% for switches) to detect future deviation trends.
- **Implement periodic polling** (e.g., via SNMP `ciscoMemoryPoolUsed`/`ciscoMemoryPoolFree` OIDs or a pyATS scheduled job) to track Processor Pool memory over time and generate automated alerts if utilization approaches the 80% threshold.
- **Set alert thresholds** at two levels:
  - ⚠️ **Warning:** > 70% utilization
  - 🚨 **Critical:** > 80% utilization
- **Monitor top memory-consuming processes** periodically. Key processes observed with the highest `Holding` values include `IP ARP Adjacency`, `CEF: IPv4 process`, `Crypto CA`, and `EEM Server` — these should be trended over time.

---

## Conclusion

All four IOS-XE devices in the testbed — `R1`, `R2`, `SW1`, and `SW2` — are operating with **healthy Processor Pool memory utilization**, ranging from approximately **13.80% to 16.40%**. No device has breached or approached the 80% alerting threshold, and no issues are raised at this time. The environment demonstrates consistent and symmetric memory profiles across device pairs, which is indicative of a stable and well-provisioned network. Ongoing monitoring is recommended to maintain visibility into memory trends as the network evolves.
