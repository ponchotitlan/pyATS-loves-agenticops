# Network Assessment Report

## Executive Summary

A memory utilization assessment was performed across all **4 IOS XE devices** present in the testbed inventory. Data was collected in real time using `show processes memory` on each device. All devices were evaluated against a **80% utilization alert threshold**. The pyATS validation suite returned a **100% pass rate** — no device exceeded the alerting threshold. The environment is currently operating with comfortable memory headroom across all nodes.

---

## Scope & Assumptions

- **Devices in scope:** `R1`, `R2`, `SW1`, `SW2` — all running **Cisco IOS XE** on the IOL (IOS on Linux) platform.
- **OS types covered:** IOS XE (routers and switches). No IOS or IOS XR devices were found in the inventory.
- **Commands attempted:**
  - `show platform resources` — **not supported** on IOL-based platforms (rejected with `% Invalid input`).
  - `show processes memory summary` — **not supported** on this platform variant.
  - `show processes memory` — **successful** on all 4 devices; used as the authoritative data source.
- **Memory pool analyzed:** Processor Pool only, as reported by the device's process memory table header line.
- **Alert threshold:** Memory utilization **> 80%** triggers an issue flag per the assessment brief.
- **No IOS or IOS XR devices** were present in the inventory at the time of assessment. The report reflects only the devices that were discovered and reachable.

### Key Observations

- **Routers (`R1`, `R2`)** exhibit slightly higher memory usage (~16.4%) compared to the switches. This is consistent with the additional routing processes running (`CEF: IPv4`, `Crypto CA`, `EEM Server`, `Crypto IKEv2`, `EST Client`), which are among the top memory holders on those devices.
- **Switches (`SW1`, `SW2`)** show the lowest utilization at ~13.8%, reflective of their layer-2-oriented process set (e.g., `Spanning Tree`, `UDLD`, `DTP Protocol`, `VLAN Manager`).
- Memory figures are **nearly identical between paired devices** (`R1` ≈ `R2`, `SW1` ≈ `SW2`), suggesting symmetric configurations and consistent workloads across redundant pairs.
- The process `Crypto CA` is one of the largest individual memory consumers on routers, holding **~1.1 GB allocated** (with most freed back), indicating active PKI/certificate operations.

## Risks & Considerations

- **No alerts raised:** No device exceeded the **80%** memory utilization threshold. The environment has significant memory headroom (>80% free on all devices).
- **IOL platform limitations:** The `show platform resources` and `show processes memory summary` commands are not available on IOL-based devices. If physical hardware or other platforms are added to the inventory, these commands should be re-evaluated for broader compatibility.
- **No IOS / IOS XR devices present:** The inventory contained only IOS XE devices. Should IOS or IOS XR devices be onboarded, their memory data collection commands (`show processes memory` for IOS, `show memory summary` or `show processes memory detail` for IOS XR) will need to be validated separately.
- **Point-in-time snapshot:** This assessment reflects a single moment in time. Memory can grow dynamically under traffic load, routing table expansion, or active crypto sessions. Continuous monitoring via SNMP or streaming telemetry is advisable.

---

## Recommendations

- **No immediate action required** — all devices are well within safe memory utilization levels.
- **Implement continuous monitoring:** Deploy SNMP polling or telemetry-based memory tracking with alerting at the **80% threshold** to proactively detect memory pressure in production.
- **Establish a baseline:** With current utilization at 13–16%, document these readings as the operational baseline for future comparative assessments.
- **Schedule periodic re-assessment:** Re-run this check after any significant configuration changes (e.g., adding routing protocols, enabling additional crypto features, or scaling up VLANs/VRFs) to confirm memory impact.
- **Review high-memory processes:** On the routers, processes such as `Crypto CA`, `EEM Server`, and `EST Client` are the top individual consumers. These should be reviewed if they grow significantly over time.
